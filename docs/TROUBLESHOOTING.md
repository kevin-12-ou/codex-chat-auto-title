# 安装与排障 / Troubleshooting

## Hook 没有出现或不执行

在完整源码目录运行 `python -X utf8 manage.py doctor`。检查 Python 包含 `pythonw.exe`、`codex --version` 可执行、`CODEX_HOME` 指向预期目录。刷新 Codex 的 Hooks 设置；必要时在方便时重新打开应用。配置存在不代表已信任，必须由用户审阅信任。

不要安装在含 `%`、`&`、`$` 等 shell 特殊字符的路径。本工具拒绝这类路径以免 Hook 命令被错误解释；空格和中文路径允许。

## 为什么没有给某条聊天起名

只有新的 Stop 事件会入队。等待 10 分钟空闲，再看 `manage.py status`。手动标题、未知标题、置顶、归档、执行中或已经处理过的聊天会跳过。刚安装不会自动清理所有旧聊天。保守识别会漏掉一些默认标题，这是保护现有标题的取舍。

## 模型失败、额度已用完

确认设置中的模型属于当前账号可用模型；程序不自动切换备用模型。失败计入每日上限，保留原标题，退避 30 分钟；同一事件不自动重试。再次在该聊天正常回复后才能重新入队。默认每天合计 30 次，不是每条聊天 30 次，也不是每天自动发满。

如果 `config.toml` 中 MCP 服务器名称含点等无法安全覆盖的字符，轻量调用会拒绝起名；不要为此绕过隔离。检查配置，或报告最小脱敏复现。CLI 和桌面使用不同登录/配置时，先统一你预期使用的环境。

## project 中聊天看起来消失、旧聊天跑到前面

先清除搜索或筛选，检查项目、侧栏分组及排序偏好。project 有时根据工作目录判断；数据库 `project_id` 为空不一定代表不属于某个 project。

本工具只改显示标题，不改 `cwd`、`project_id`、分组、置顶或排序时间。起名过程中移动聊天会取消写入；事务中发现其他字段变化也会回滚。Codex 自己打开/恢复/同步/迁移聊天仍可能改变排序或侧栏显示。本项目不会强行倒写真实活动时间，也不会自动切换你的全局排序方式。

如需报告问题，请附 Codex/CLI/Python 版本、已脱敏的相关字段前后差异和复现步骤。不要直接上传数据库、聊天正文或整个 runtime 目录。

## 仍有弹窗或卡顿

先 `manage.py disable` 对照观察，再 `enable` 恢复。确认旧版本或其他自动命名任务没有同时运行。原生进程隐藏参数能消除本工具启动的控制台，但不能证明其他程序、插件或 Codex 本身不会弹窗或卡顿。

## 更新、移动目录、停止与卸载

更新前先 disable，保留 `runtime/`，覆盖源码，再 enable。不要在后台运行时删除安装目录。移动目录前在旧目录 uninstall，复制源码和私人 runtime，再在新目录 install，重新审阅信任新命令。

`stop` 只停当前进程，Windows 自启可能再次启动；`disable` 持久关闭入队和处理。`uninstall` 保留原标题日志、计数和已改标题。若要恢复标题，先预览 `background.py restore` 再考虑 `--apply`；不要整库覆盖。
